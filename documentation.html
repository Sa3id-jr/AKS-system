Project Overview

This project is the Ava Kirolos Scout Group website. It is a scouting administration system used to manage scouts, leader accounts, patrols, attendance, follow-up tasks, records, requests, and reporting.

The system is built with static web pages that communicate with Supabase as the backend database service. User authentication, authorization, search, editing, filtering, charts, PDF/Excel exports, and the database operations are handled by front-end JavaScript code and Supabase queries.

Navigation Roles

Master

Has access to all pages and all records. Can approve leader requests, approve scout requests, manage leaders, view all sectors, and operate the highest-level administrative workflow.

General

Has broad operational access across the whole group. Can open management dashboards, approve leader and scout requests, and manage organization-wide actions.

SectorLeader

Can see the sector/stage assigned to them. This role can manage scout and patrol related actions in their sector and review sector-level requests.

TroopLeader

Can see scouts and patrol operations within the assigned troop. Can create or manage follow-up tasks and send edit requests for approval instead of applying direct edits.

Viewer

Limited login visibility. The system logs them in but restricts data access for normal scout operations.

Core Data Tables

  • leaders: login accounts and role definitions.
  • scouts: scout profile and registration data.
  • attendance: attendance and scoring records.
  • patrols: patrol names and relation to troop/sector.
  • scout_requests: requested scout edit/delete activities.
  • follow_up_tasks: follow-up tasks with assigned leader IDs/names.

How to Use The Website

  1. Open the login page at index.html.
  2. Log in with the leader username and password from the `leaders` table.
  3. After successful authentication the session is saved in local storage.
  4. Use the home page cards to navigate to the relevant system areas.
  5. Use the `dashboard.html` page to search, filter, review, and manage scout records.
  6. Higher-level roles approve pending requests when they are created by lower-level users.

Security / Production Notes

The current implementation stores a signed-in leader session in the browser using `localStorage` and runs most database operations through front-end Supabase calls. For a production system the next step should be to move write operations behind a secure API and enforce Supabase Row Level Security policies.
